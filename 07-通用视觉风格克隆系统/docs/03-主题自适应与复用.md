# 主题自适应、四版复用与迭代

## 风格固定，内容与适配单列

风格档案 `style` 只保存视觉关系。`task.frames` 保存核心主体、状态、环境、焦点、准确文案与目标版式；`bridge` 解释这些内容如何用原媒介表现。风格哈希覆盖整份 style，以稳定排序后的 JSON 计算 SHA256，换主题时不改变。哈希相同只证明档案相同，不证明图像相同。

| 模式 | 使用方法 | 固定项 | 可变项 |
|---|---|---|---|
| TEMPLATE | 输出带槽位母版 | 十三系统与五锚点 | 待填写主题；不虚构即用成品 |
| SWITCH | 完全更换题材 | 全部 style | 主体、场景、画幅、内容 |
| EXPAND | 同一题材输出多帧 | style＋独立 series_anchor | 每帧行动、场景与叙事进程，当前实现 2—9 帧 |
| TRANSFER | 跨品类，如绘画到字体 | 线质、媒介、光色与疏密语法 | 按已批准的条件规则重新布局 |
| 单字段修订 | 调用 reviseRule | 其余系统逐项不变 | 一个系统的双语规则；返回前后哈希和审计记录 |

本地编译器不擅自猜主题类别。视觉模型在提取/任务规划时建议类别，由用户或档案作者在 `category` 中明确为 character/product/space/poster/typography；编译时据此选中对应的细节重心规则。这是规则驱动适配，不是另一个隐藏的图像识别模型。

## 四道主题协调

色域：将新对象的固有色映射到底色、结构色和强调色；若精确品牌色或数据色标不能改变，报告冲突，优先保留真实信息。不得偷偷修改风格调色板。

材质：用原媒介表现新的物理材料。例如手绘档案中的金属可用结构轮廓与留底表达反光，不自动加入摄影反射或光线追踪词。具体画法必须来自当前档案，系统没有统一“水彩默认值”。

空间：将新元素绑定到原来的高低密关系和阅读顺序。对象变多先分组、分版，不挤压文字或篡改数据。如果已锁定的构图完全无法容纳目标版式，应解释冲突并请用户选变体，而不是同时输出相互矛盾的要求。

细节：角色强调神态姿势，产品强调结构，空间强调入口关系，海报强调阅读顺序，字体强调骨架字怀。这些是可审改的桥规则；当前类别默认由档案作者填写，不声称适用于所有具体风格。

## 构图固定与跨品类自由的处理

从单张风景图不能武断提炼成“所有后续图必须主体位于同一坐标”。应把稳定的疏密逻辑写为规则，把具体坐标标成条件项；只有用户明确要求严格布局时才固定坐标。如果原档案已经固定了互不兼容的构图，跨品类迁移需要创建有新 ID 的风格变体并记录变更，不能维持旧哈希又暗改规则。当前版本采用这种保守处理，不宣称同时实现绝对构图锁定与任意布局自由。

## 四版输出契约

两个 JSON 均有四个顶层区域：元数据、锁定风格、自适应桥、主题槽。保存或复用时改主题任务后重新编译，不手改一份语言版本而让另一份滞后。

中文简易版提供通用槽位行和已填即用行，固定核保持原样，成品要求 90—140 个汉字。计数只统计 Unicode 汉字，不把数字、标点和英文字母算作汉字。超长直接报错，要求精简主题或重新审核短核，绝不静默截断关键信息。母版保留占位符，不按成品字数验收。含精确文字、长文案或复杂版式时改用自然语言版，短版不承担这类信息的无损表达。

自然语言中英各自输出母版和即用版。P1 是固定的媒介与造型规则，P2 包含可替换主题、画幅、系列内容锚点和适配桥，P3 是固定的光色、空间和禁令。更换画幅也只修改 P2，P1/P3 可逐字对照。编译器保留全部十三系统文本；不要另加“完美、顶级、震撼”等空泛词稀释规则。

## 与现有信息图作业的连接

01 确定数据主逻辑，05 保证数值口径与尺度；07 提供视觉风格。装饰色不能覆盖数据类别含义，笔触不能改变柱长，纸纹不能遮住数字。使用 ISOTYPE 外观而没有定量单位规则时标注 ISOTYPE-inspired，实际计数回归 03。Gestalt 可读性按本地 04 的十三研究条目核查，不能套用参考仓库不同编号。06 的第 06 阶段可调用本系统，第 08 阶段保存四版输出与迭代记录。

一次生成失败后记录“偏差—字段—修改—再生成—复核”；若修改媒介等核心锚点，建立新档案版本，并重新审定短摘要。`reviseRule` 仅保证一项规则变化，新的视觉效果、摘要适切性和翻译仍需复核。
