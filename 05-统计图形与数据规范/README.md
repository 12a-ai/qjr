# 数据规范｜先确定记录，再确定图形

## 原子化不是把文字拆成单字

每行是一个明确记录，每列是一种属性，每格只存一个值。一个标题、一段解释、一个图像路径各可以是单值。一个单元格同时写“2024年／北京／25万人”则混合了多个属性，不利于计算。

| 不合适的写法 | 规范处理 |
|---|---|
| 坐标：经度,纬度 | longitude 与 latitude 两列，另记坐标系 |
| 数量：23件 | value=23，unit=件 |
| 标签：文字型,ISOTYPE | 案例表外另建 case_id—tag_id 关联表 |
| 时间：2020—2024 | start_year 与 end_year 分开 |
| 图片直接混在数值列 | 独立 resource_id 或单个文件路径 |

## 六张逻辑表

对象表提供稳定 ID；观测表记录对象、时间、指标、值、单位；关系表记录父子/先后/关联；来源表保存出处；资源表保存图像和文本资源；派生表保存计算结果与公式。实际选题不必强行用齐六张，按关系复杂度取舍。

缺失为空并配 missing_reason；零值为已观察到的 0，不能混同。不把估计数混成实测数；文字转录、图像测量和外部补充均记录 provenance。

## 图形与问题

比较多少用同基线条形或点图；变化用有真实顺序的折线；分布用直方图或箱线图；构成用可解释分母的堆叠；空间用地图；从属用树图。没有数量时使用结构图或排版，不强造统计图。

面积编码遵循面积与数值成比例；三维体积编码若无必要则避开。截断轴、不同时间窗口、不同分母都应在比较前核查。

## 发布前的数据检查

主键唯一，关联 ID 存在，数值能解析，日期精度真实，单位一致，口径匹配，缺失可解释。以几条代表记录手算派生结果，排除重复计数。检验目的是防止错误结论，不对没有材料的模板声称已完成数据验证。
